# v1.0 QA, Documentation, and Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify the approved v1 scope on the real tailnet, resolve documentation contradictions, and deploy version 1.0.0 with a tested rollback.

**Architecture:** Treat the existing design carryovers as an evidence audit, then run automated, browser, security, and live-device gates in increasing risk order. Deploy retention archives in read-only mode first, verify parity, and enable raw deletion only after a database backup and explicit live check.

**Tech Stack:** Existing Node/React test suites, Vitest, Playwright, Tailscale, systemd, SQLite.

## Global Constraints

- Live acceptance devices: Ubuntu hub, MacBook Pro, iPhone.
- Mac mini and Desktop are not v1.0 blockers.
- No Funnel; HTTPS remains tailnet-only.
- Deployment must preserve a recoverable SQLite backup.
- `RETENTION_DELETE_ENABLED` remains false until archive parity is verified in production.
- Version sources must all report `1.0.0`.

### Task 3: Security and relay integration gate

**Files:**
- Create: `hub/src/ws-security.test.js`

**Interfaces:**
- Produces repeatable upgrade-path evidence for `/pty`, `/run`, and `/agent`.

- [ ] **Step 1: Add a production-server child-process harness**

In `ws-security.test.js`, reserve a loopback port with `net.createServer().listen(0)`, close the
reservation, create a temporary `devices.json`, and spawn the real `hub/src/server.js` with:

```js
const child = spawn(process.execPath, ['src/server.js'], {
  cwd: HUB_DIR,
  env: {
    ...process.env,
    HUB_PORT: String(port),
    HUB_PIN: '2468',
    SESSION_SECRET: 'security-test-secret-32-bytes-long',
    DEVICES_FILE: devicesFile,
    DB_FILE: ':memory:',
    RETENTION_DELETE_ENABLED: 'false',
  },
  stdio: ['ignore', 'pipe', 'pipe'],
});
```

Poll `/healthz` until ready. The test cleanup sends `SIGTERM`, waits for exit, and removes the
temporary directory. Login with `POST /auth`, retain the `Set-Cookie` value, and mint each
single-use token with `POST /pty/token`.

- [ ] **Step 2: Add security integration cases**

Use real HTTP and `ws` clients to assert:

```js
await rejectsUpgrade('/pty?device=hub', { origin: GOOD_ORIGIN }, 401);
await rejectsUpgrade(`/pty?device=hub&token=${token}`, { origin: 'https://evil.invalid' }, 403);
await rejectsUpgrade(`/pty?device=ghost&token=${freshToken}`, { origin: GOOD_ORIGIN }, 404);
await rejectsUpgrade(`/pty?device=ghost&token=${singleUseToken}`, { origin: GOOD_ORIGIN }, 404);
await rejectsUpgrade(`/pty?device=ghost&token=${singleUseToken}`, { origin: GOOD_ORIGIN }, 401);
```

Repeat bad-origin and unknown-device checks for `/run` and `/agent`; `/agent` also rejects an
unknown or cross-device session. Using an unknown device/session proves the trust boundary without
spawning tmux, SSH, Shell, or Agent children.

- [ ] **Step 3: Run security tests**

Run: `cd hub && node --test src/ws-security.test.js`  
Expected: all upgrade status assertions pass and no child process is spawned for rejected paths.

- [ ] **Step 4: Commit**

```bash
git add hub/src/ws-security.test.js
git commit -m "test(security): cover websocket upgrade trust boundaries"
```
