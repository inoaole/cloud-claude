- `feat(v0.6/T1): agent.js — claude stream-json relay core (mapEvent + command builder)`
  The IO-free, tested core of Agent mode. `mapEvent` translates claude's stream-json JSONL →
  phone WS events (assistant text / thinking / tool_use / tool_result / result / status /
  assistant_delta), mapped against the real event shapes captured in the T0 spike
  (designs/agent-spike-20260701) — never throws on a malformed event (codex #17). `buildAgentCommand`
  builds the `ssh -tt … setsid bash -lc 'cd <cwd> && exec claude -p --input-format stream-json
  --output-format stream-json --include-partial-messages --permission-mode acceptEdits'` command:
  `-tt` so SIGINT/Stop propagates (D4), `setsid` so killing ssh reaps claude + children (codex #7),
  cwd validated by `assertCwd` (absolute, no traversal/metachars, optional allowedRoots — codex
  #5/#14), device fields guarded by `assertSafeArg`. `wrapUserMessage` = the verified stdin schema.
  Tests: hub `node --test` +14 (38 total) — event mapping for every block type + malformed input,
  cwd guard, command shape for Mac/hub. claude runs ON the device (its own auth); hub only pipes.

- `feat(v0.6/T3a): WS /agent bridge — phone ⟷ hub ⟷ ssh ⟷ claude stream-json`
  `bridgeAgent` spawns the agent command (detached, own process group), parses claude JSONL by
  line → `mapEvent` → WS, and pipes `{type:'user'}` messages to claude's stdin. **Keep-alive
  reattach (T-B):** on WS close the child lives ~45s with output buffered (bounded 500) so a
  reconnect re-attaches the same live stream; grace-expiry SIGTERMs the group. Backpressure =
  bounded disconnect buffer; malformed/huge JSONL lines are skipped/capped (codex #8/#17). Stop
  (D4) = SIGINT the group. The `/agent` upgrade path validates the session belongs to the device.
  **Debugged 3 real integration bugs before it worked:** (1) ssh flattens argv after the host →
  the remote command must be ONE shell-quoted string; (2) `-tt` (pty) echoes our stream-json
  stdin into claude's stdout and corrupts the event stream → use a plain pipe, and rely on
  stdin-EOF-on-ssh-close for cleanup; (3) a zsh user's brew PATH isn't on bash's login PATH →
  `claude: not found` → prepend `/opt/homebrew/bin` (same fix as the shell relay). `agent.js`
  buildAgentCommand updated accordingly (43 hub tests green).
  **VERIFIED end-to-end on the hub against real claude:** open agent session on MacBook Pro → send
  a prompt → `status ready · tool_use(Bash echo) · tool_result · assistant + assistant_delta ·
  result ok ms=9144`. Every block type + token streaming flows through the bridge.

- `fix(v0.6): hub crash on agent-exit (null ws) + honest hub-down error`
  Two bugs surfaced when the phone showed "Wrong PIN": (1) `bridgeAgent`'s `child.on('exit')`
  did `b.ws?.readyState === b.ws.OPEN` — when the socket had detached, `b.ws` is null and
  `b.ws.OPEN` threw a TypeError that **crashed the whole hub process** (so every agent-exit after a
  disconnect took the server down → tailscale serve 502). Guard: `b.ws && b.ws.readyState === b.ws.OPEN`.
  (2) `lib/api.login()` mapped ANY non-ok / non-429 / non-503 to `bad_pin`, so a 502 (hub down) read
  as "Wrong PIN". Now only 401 → bad_pin; 5xx/gateway → `unreachable`, and Unlock shows a distinct
  "Can't reach the hub — try again" (keypad stays enabled). +2 tests (api 502→unreachable, Unlock
  offline message). The PIN was always correct — the hub was just down.
